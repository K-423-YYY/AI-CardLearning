# 开发者构建指南

## 本地运行

```bash
python serve.py
```

访问 `http://127.0.0.1:8765`。

`serve.py` 使用自定义 MIME 映射，保证 `pdf.mjs` 与 `manifest.webmanifest` 正确加载；不要直接用 `python -m http.server` 代替。

## 测试

```bash
npm test
```

浏览器端到端测试需要本机 Chrome，并先启动本地服务器：

```bash
python serve.py
node tests/e2e-smoke.js
node tests/e2e-verify.js
```

## PWA

`app/manifest.webmanifest` 提供安装元数据，`app/sw.js` 负责静态资源缓存。部署时把 `app/` 放到任意 HTTPS（或 localhost）静态服务器即可。

## Windows 桌面版（Electron）

```bash
cd desktop
npm install
npm start
npm run dist
```

产物在 `desktop/dist/`，包含 NSIS 安装包和便携版 `.zip`。主进程通过 preload 暴露 `window.desktopAPI`，导出/导入备份会使用系统原生文件对话框。

> 说明：v0.1 默认使用浏览器 IndexedDB 作为本地存储，数据位于 Electron 用户数据目录；`better-sqlite3` 作为可选依赖保留，后续版本可平滑切换。

## Android APK（Capacitor）

```bash
cd android
npm init -y
npm install @capacitor/core@6 @capacitor/cli@6 @capacitor/android@6
npx cap add android
npx cap sync android
cd android
./gradlew assembleDebug
```

生成 APK 后，正式发布前：

- 将 `AndroidManifest.xml` 的 `android:allowBackup` 改为 `false`
- 使用自有签名或调试签名

前置环境：Node.js 18+ 与 Java 17+（推荐 Java 21）。CI 已固定使用 Capacitor 6，避免新版 Capacitor 对 Java 版本要求过高导致构建失败。

## GitHub Actions

仓库根目录 `.github/workflows/build.yml` 已配置 Windows 与 Android 两条构建流水线：

- 推送 `v*` tag 或手动触发时执行
- Windows：构建 NSIS + portable
- Android：安装 Capacitor、生成 Android 工程并 `assembleDebug`
- 构建产物上传为 workflow artifacts，可手动发布到 Releases
